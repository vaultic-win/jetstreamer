## Preserve the actor for its entire lifetime

The extractor compares its complete actor snapshot, including systemd's raw `ExecStart` display,
before release and again before final completion. A global `systemctl daemon-reload` can reset
the display's runtime PID and timestamps even while the real PID, invocation, executable and
command remain unchanged. That correctly fails this existing equality check.

Do not run global `daemon-reload` from waiter start through actual terminal capture. This includes
unrelated unit installation and later compiler setup. Do not rewrite the waiting receipt,
normalize its actor, restart a healthy extractor, or weaken equality to recover a display change.
Use a fresh isolated attempt after a genuine failed waiter, preserving all original evidence.

Prepare static material before starting the waiter. New persistent service and timer files can
load on demand with `systemctl start`, without a global reload. Verify that behavior on the actual
host with a bounded synthetic fixture before relying on it; preserve the unchanged live anchor
metadata and persistent-unit results. Never modify a loaded guard configuration during live
extraction unless its exact qualified lifecycle supports that change.

## Complete the normal guard protocol

- Use the actual waiting invocation and admitted floor in the immutable guard plan. Preserve its
  exact output cap, receipt directory, capabilities, writable paths and command hashes.
- The existing completed-guard collector requires PID 1's successful command-bearing description.
  Set the guard service's `Description` to `[systemd-run] ` followed by its complete, exact
  `ExecStart` command. A human-only description does not satisfy this collector. This is evidence
  formatting, not permission to substitute a different command or invent manager history.
- Start the timer before the normal guard invocation, or run another normal guard invocation
  after starting the timer. An `OnUnitActiveSec`-only timer started after an unreferenced short
  oneshot was collected can remain `active (elapsed)` without a future deadline. Require
  `active (waiting)`, a future deadline and a genuine healthy completed sample with producer
  stopping enabled before release. A capability-only sample is insufficient.
- Release within the actual 300-second waiter deadline and 900-second admission lifetime. A
  failed or expired attempt remains preserved; never restart into its occupied output tree.
