# Resource-limited epoch 203 canonical-root prefix

The separately gated `jetstreamer-epoch203-root-prefix-resource` utility is a
private qualification attempt, not ordinary replay, a full-epoch peak promise,
or publication authority. Build it with `--features epoch203-root-prefix-resource`.
It keeps the exact retained snapshot, v1.6.16 store8 worker and parent used by the
bounded comparisons, with the existing 16-thread setting. The one-thread
comparison saved only 1.24% scratch and took 4.38% longer; it is not a reason to
lower a full-prefix budget or change healthy producers.

The fixed scope is bootstrap 87,695,515, recorded output 87,696,000 through
88,127,580 (431,581 slots), and no successor tail. This leaves 419 epoch slots
unrecorded; even success is not a complete epoch and cannot acquire a canonical
checksum sidecar. Use the existing focused route and the exact two-name bootstrap
and canonical-root checkpoint file. Never shorten or borrow the launch authority
of the complete-span package that continues through the next epoch's root.

The strict hash-bound plan uses schema
`jetstreamer-private-epoch203-root-prefix-resource-plan-v1` and the same fields as
the bounded-resource runner. Units must start with
`horizon-qualify-203-root-prefix-resource-`; direct private run roots must start
with `root-prefix-resource-203-`. The parent digest, worker digest, snapshot name,
size and digest, target/root, archive name, checkpoint names, minimum initial free
space (3,185,678,193,366 bytes), and maximum runtime (72 hours) are build-bound.
The invocation uses a preseeded private genesis/ledger, isolated scratch/output,
one explicit `--verify`, the exact root, and no R2 credentials.

Unlike the benchmark runner, reaching a progress or native-checkpoint marker
does **not** signal the child or declare success. The parent must finish
naturally with exit zero and a private segment manifest matching the exact
worker, root accounts hash and 431,581-slot range. The runner captures cgroup
counters while its own service remains alive, binds the manifest digest and
archive length, and writes a no-clobber `receipts/root-prefix.json`; a failure
writes `receipts/failure.json` and preserves artifacts. Code 1 is never normalized
as natural root success. An independently validated full archive reread remains
mandatory; a producer manifest or wrapper success is not that independent event.

An optional frozen capture at the root records scratch and live AccountsDb state.
The captured terminal scratch limit is 768 GiB. It is not a continuous scratch
peak proof. A missing optional capture must be reported rather than throwing away
a naturally completed parent artifact; a measured bound violation fails the
attempt. The runner always denies full cold-epoch peak qualification.

Fresh admission must account for the complete incremental capacity envelope,
including restore, scratch, output and guard-growth buffers. One conservative
candidate envelope is 960 GiB (768 scratch + 128 archive + 64 buffer), 192 GiB
hard memory with 160 GiB high, and 16 CPU cores. These are capacity limits for a
guarded experiment, **not evidence that the full prefix fits**. Keep all older
invocation-bound growth claims, protected/reserve memory, the current twice-mean
century floor and VMA ceiling intact. Explicitly revalidate any completed-job
reservation release or measured growth-claim revision in a new admission
generation; never edit an active controller or old guard underneath its work.

Use the standalone guard's normal natural-completion profile, not a
target-stopped `bounded_canary`/`bounded_measurement` exemption. Set its actual
free-space stop to protect the older growth, century floor and growth buffer,
bind the exact invocation, and prove one real readable worker and a clean
sandboxed first fire before unattended execution. Normal workerless parent
archive drainage is allowed; the production and experimental hard limits,
service identity and filesystem checks still apply. Keep the one 30-minute
observer cadence and classify the unit as private diagnostic qualification, with
no public status countdown.

After success, independently validate the complete retained prefix and its
canonical checkpoint. Only then consider the separately reviewed epoch203
restart tuple, 419-slot suffix and V4 assembly path described in the checkpoint
continuation runbook. The epoch213 continuation runner is not reusable authority.
All full/plugin, provenance, publication, authenticated upload/readback and
sidecar gates remain independent. Epoch301 remains private.

The independent `jetstreamer-qualification-verify` must support the runner's
literal `epoch-203-prefix.jet` name. Its explicit filename exception is restricted
to the exact bootstrap, output start, canonical root, v1.6.16 revision and unchanged
worker digest above. It still deeply rereads the complete archive and segment,
checks the canonical root accounts hash and rejects any canonical sidecar. Do not
rename the retained archive or relax another epoch's naming gate to fit an older
validator. Prefix validation is not full-epoch or publication qualification.

Use the validator's optional `--receipt=/PRIVATE/epoch-203-prefix.validation.json`
to persist the independent result natively. The existing receipt parent must be
canonical, owned by the reader and owner-only. The destination is checked before
the scan, created without clobbering, written mode0400, and fsynced together with
the bound parent directory. Failed validation writes no receipt; retain any
interrupted write for explicit diagnosis rather than overwriting it. Without
this option, the existing stdout-only interface is unchanged.

## Read-only stopped-scratch qualification

`jetstreamer-epoch203-stopped-scratch-check` is restricted to the exact October21
reserve-stopped root-prefix invocation and its original private run directory.
It accepts only `PLAN --plan-sha256 HEX --self-sha256 HEX`; there is no deletion
or execute mode. Its strict plan binds the immutable incident, source review,
original exact-build receipt, and a private no-clobber `check.json` destination.

The checker independently rehashes the historical parent/runner source from
their fixed Git objects, matches the retained parent to the original build,
proves the failed non-restarting owner and stopped guard timer, checks queued
jobs and staged unit inputs, and performs complete streaming process-reference
scans. Only the independently hashed exact terminal owner's transient fragment
is excluded from the staged-file census. All other matches fail closed.

It hashes the entire retained partial archive and required inputs, inventories
the exact scratch tree without following links, rejects foreign devices/owners,
hardlinks, writable peers and nested mounts, then repeats ownership/reference/
tree/retained-identity checks. Legacy read/execute bits are permitted beneath the
owner-only scratch root; the stricter existing RAM-retirement policy is unchanged.
The resulting catalog binds per-entry identities and clocks, not scratch-file
contents or resumability. Partial archive hashing is not semantic verification.

A positive receipt authorizes no removal, replay, admission or publication.
Preserve the partial archive, inputs, failed unit and all stop evidence. A
separately reviewed and qualified retirement implementation, with its own intent,
reference checks, preservation proof and interruption handling, remains required
before any scratch unlink. Existing singleton/RAM/restore-only retirees must not
be pointed at this unsupported layout.
