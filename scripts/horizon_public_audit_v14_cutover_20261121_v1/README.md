# Natural epoch 73 public audit handoff

This host-specific transition uses the full native report left by the old chronological audit after it closes its epoch-73 reader on a change of reader inputs. The existing benchmark and the scheduled fleet publisher retain their own reservations. The file watcher subscribes to the original attempt on the HOME-backed state filesystem. Its handler exits after the transition. The controller uses the same systemd service, settings and audit lock.

The dual-capable fleet observer belongs in its own normal deployment. Run the sealed native `qualify` first to check the genuine incumbent, original receipts, source closure, scheduled fleet, existing independent workers and root's isolated v14 acceptance and resume evidence. Run `publisher` between fleet samples to switch the single existing publisher. It checks the actual consumer lock, pending timer and native sleeping process. The previous launch proof remains in the receipt chain.

Install the systemd path and oneshot only after verifying the sealed helper and root's authorized operating envelope. The event must be from the pinned original attempt. The helper fences the exact old parent through a pidfd after the original decoder exits. It rechecks the cgroup, finalized native report, current reader inputs, existing 73 result hashes, new seal, fleet and timer. A replacement decoder or an unknown process leaves the incumbent in service. The recovery command releases a fence it owns. Starting the prior controller as a new invocation requires a failed new start, empty cgroup, durable old-owner closure and unchanged result set.

Use the existing 30-minute observer and the accepted epoch-73 result event for follow-up. The sealed `active` command checks the new native identity, all retained accepted-result hashes and current progress. Once 73 is accepted, it checks its frozen archive identity, original native report and both linked old/current reader proofs, and reports whether the original playback was recovered.
